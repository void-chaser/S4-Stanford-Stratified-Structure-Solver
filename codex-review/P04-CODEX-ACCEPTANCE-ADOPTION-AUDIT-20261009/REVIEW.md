## 是否按要求执行，哪里需要纠偏

上一条提示词明确限定离线验收、不 apply、不 Git 写入、不新增 native。本轮停止在采纳计划完全符合该条要求；不能因它没有生产提交判定其失职。三个脚本重跑成功，发现并纠正字段读法也不是模型上限证据。

采纳计划的下列判断需要调整：

1. **测试 seam 不应仅凭目录位置判为产品缺陷。** rcwa.cpp 的引用/调用均受 S4_TEST_EIGEN_INFO 控制，默认 Makefile 未启用该宏。可以把头文件移到 testing 并调整测试构建 include 路径；但直接删除三个宏块会改变已经用于生产可达错误传播验证的测试能力。D002 RNP driver 的 D002_TEST_SEAM 是另一种机制，不能用它替代 S4 上层传播测试。保留受控 seam 或提供等价测试 overlay，并检查普通构建不启用注入。迁移建议与实际运行失败应分开陈述。
2. **非恒等上下置换属于既定关闭要求。** 路线图要求布局/上下置换，GitHub #2 还有非单位 scale[] 与 scalea 的分别验收。旧限额运行未覆盖是事实；新增针对性回归应在生产采纳阶段完成，不能把既定必要项仅称作可选声明边界。无需重开旧冻结 RUN 或全量历史控制链。
3. **GetWaves 缺登记是范围管理缺口。** 不能由此推出实际代码错误，也不需要无限审批。D001/D002 最小批次可延后独立 GetWaves 改动，保留相关旧实现；若后续单独纳入，应新增工作项并验证其 API 契约。Python 未暴露该接口时，错误表占位文本不是用户可见阻塞。
4. **89 项测试资产不是已确定的最小回归集。** authority 两文件不在 102 项采纳变更内，不能从 89 再减二凑数。只提取可恢复源码/输入/参考/runner，确认 fresh checkout 能运行；不整体纳入约 5.3 万行历史工具或控制平台。
5. 102 项三方比较只覆盖该 manifest；不代表整个生产树干净。现有 DEFECTS.md 修改和未跟踪目录应保留，不能通过 git add -A 一起提交。
