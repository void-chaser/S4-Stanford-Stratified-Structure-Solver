== E6b-5 [SCOPE NOTE on the solved semantics, I4] ==
S4.cpp: sol->solved is an int array indexed by layer index i (Solution_.solved, S4.cpp:195-197; allocated 1756; zeroed 1764).
Writers of solved[] (verified by grep and by reading the lines):
  - S4.cpp:2012  (inside the full-solve branch, after a successful SolveInterior over the whole stack): sets solved[i]=1 for ALL i = 0..n_layers-1.
  - S4.cpp:2225  (solution_cleanup of Simulation_ComputeLayerSolution): sets solved[which_layer]=1 ONLY if error == 0.  which_layer is the index of the requested layer (see 2195-2200).
  - Simulation_DestroyLayerSolutions (S4.cpp:2855-2868) sets solved[i]=0 for all i.  Not called by the driver.
Simulation_DestroyLayerModes (S4_Simulation_DestroyLayerModes, S4.cpp:1364-1372) clears layer modes but does NOT touch solved[].  The twice route (S4FMM_TWICE=slab) calls it for layer 1.
Consequence for I4: "request layer solved == 0" means solved[which_layer] == 0 at k_fail, where which_layer is the requested layer of the failing call.  The code sets it to 1 only on success (error == 0), so at a failing call it stays 0 unless an EARLIER successful solve already set it.  Therefore I4 is checked as solved[req] == 0 at k_fail; the request layer for the driver geometry is the layer containing xyz0[2] = 0.05 (found by thickness at S4.cpp:4288-4300; the driver uses layer index 1, Slab, with thickness 0.5 at S4.cpp setup; the layer index is re-read from the state probe, not assumed).
Caveat: at k_fail an EARLIER full solve (the 2012 branch) would set solved[i]=1 for all layers.  Rule (fixed in advance, no re-definition): if at k_fail solved[req] == 1, the point is judged I4 VIOLATED and the case is reported to the user (STOP condition of the brief: "I4 semantics does not match the definition").  No point is re-classified to make I4 pass.

== E6b-6 [USER RULING U13; PLANNER ERROR in brief section 4, corrected; status INFLUENCED] Snapshot indices follow inj_call, not route ==
Planner error: brief section 4 fixes k_fail = "once 1 / twice 3" and k_retry = "once 3 / twice 4" by ROUTE.  That is wrong for the 66
points with route twice and inj_call = 1: their failing call is call1, so the first snapshot after the failure is 1, not 3.
Facts (from MAP_R6b_ALL.tsv, columns route and inj_call; counted in R6b): twice & inj_call=1: 66 points; once & inj_call=2: 0;
inj_call >= 3: 0.  (The R6 probe used inj_call=1 for a once point; this agrees.)
User ruling U13 (recorded here verbatim in substance):
1. Snapshot indices follow inj_call, not route.  The retry call = inj_call + 1.
     k_fail     = snapshot after the call inj_call:   inj_call=1 -> 1;  inj_call=2 -> 3
     k_preretry = last snapshot before the retry call: inj_call=1 -> 2;  inj_call=2 -> 3
     k_retry    = snapshot after the retry call:       inj_call=1 -> 3;  inj_call=2 -> 4
   Any point with inj_call >= 3, or a once-route point with inj_call = 2, is a STOP (report, do not infer).
2. Which snapshot each invariant uses:
   I1, I2, I3, I4: k_fail.
   I5: reference snapshot is k_preretry (not k_fail).  Within the retry interval ComputeLayerModes is entered only for layers with
       modes == NULL at k_preretry, at most once per layer; the retry rc == 0.  For twice & inj_call=1, layers destroyed by
       DestroyLayerModes between k_fail and k_preretry are listed separately in the note.
   I6: the output of the retry call is compared byte-for-byte with the output of the SAME call number in a fresh no-injection control run.
3. Driver change (replaces S4FMM_DUMP_RETRY): the driver writes the output of call1, call2, call3 to files call1.txt, call2.txt, call3.txt
   in the directory named by S4FMM_DUMP_DIR (must be under $EV).  The judge selects the file as inj_call+1.
   The legacy S4FMM_DUMP (call3 only) is kept unchanged.  The driver file is driver_r6b_state.cpp (to be edited accordingly; it has NOT been run for R6b judgement yet).
4. Pre-registration: if REGISTRY_S4_PRE_R6b_STATE.tsv is written, it carries columns inj_call, k_fail, k_preretry, k_retry, retry_call.
   If it has already been written and hashed, the original is NOT edited; a new file REGISTRY_S4_PRE_R6b_STATE_v2.tsv is written and this errata records why v1 is void.
   (At the time of U13 no pre-registration file exists in p05-s4r6b; this is recorded to avoid doubt.)
5. The map counts by (route, inj_call) are written in the pre-registration header and in the report.  twice & inj_call=1 must be 66; if not, STOP.  (Verified: 66.)
Consequence for the earlier R6b texts: section 4 of the brief (k_fail/k_retry by route) is superseded by U13 for every point.  The DRIVER header (driver_r6b_state.cpp) still describes S4FMM_DUMP_RETRY and must be updated before any run (done in the same R6b step, before the pre-registration is written).
