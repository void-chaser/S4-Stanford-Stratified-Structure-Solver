== U14 (USER RULING, the definition of I4 is corrected; the planner's error in R6b brief section 4) ==
Status: INFLUENCED.  Given before any R6c state run.

Fact basis (read-only source reading and the R6b trial log; re-checked in R6c gate):
  S4.cpp:2012          in the full-solve branch (after a successful SolveInterior over the whole stack) sets solved[i] = 1 for ALL i = 0..n_layers-1.
  S4.cpp:1339-1348     Simulation_DestroyLayerModes(S4_Layer*) frees q and the LayerModes struct and sets modes = NULL; it does NOT touch solved[].
  S4.cpp:1364-1372     S4_Simulation_DestroyLayerModes(S, id) calls the layer version; it does NOT clear solved[].
  S4.cpp:1805          Simulation_GetLayerSolution recomputes when modes == NULL, OR (copy >= 0 and the copied layer's modes == NULL), OR !solved[i].
  R6b trial log state/trial/clean_closed1d_F.gdb.log: at k=1 (after call1, no injection) solved is 0=1 1=1 2=1.
  Therefore, for a point with twice route and inj_call=2, at k_fail=3 solved[req] holds the value left by call1 (1), not a value written by the failing call.
  The R6b definition "solved[req]==0 at k_fail" is therefore wrong for those points and is replaced by I4' below.

New definition I4' (replaces I4 of the R6b pre-registration for the judgement of R6c):
  (a) the failing call does NOT change solved[req] from 0 to 1:
        solved[req]@k_fail == solved[req]@k_before,
      where k_before is the snapshot before the injected call: inj_call=1 -> k_before = 0; inj_call=2 -> k_before = 2
      (snapshot 2 is the state after the destroy of layer 1 and before call2, in the twice route; see driver_r6b_state.cpp).
  (b) if solved[req]@k_fail == 1, then at k_fail the request layer has modes == NULL (if L->copy >= 0, the modes of the copied layer are used),
      so that S4.cpp:1805 forces a recomputation.  This is the condition under which an old value of 1 does not hide a failure.
  The request layer req is NOT assumed.  It is read at each Simulation_GetLayerSolution entry with gdb (layer parameter address minus
  S->layer[0] address, divided by the struct size) and written as one line per call:  R6CREQ <call> <layer_idx>.
  The observation "solved holds the old value 1 while modes == NULL" is recorded in the ledger as OBSERVATION [source] (it is not a red point).

Consequence for the R6b pre-registration (REGISTRY_S4_PRE_R6b_STATE.tsv, sha256 f2523d14...c358):
  Its I4 ("solved[req]==0 at k_fail") is superseded by I4' for the judgement of R6c.  The v1 file is NOT edited.  The v2 file records the change (see below).
