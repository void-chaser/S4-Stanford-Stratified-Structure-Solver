== b. R3 ERRATA_3 f: how the plan NTH is read from source (reading of testing/d003/src/inject_d003.cpp, not a measurement) ==
  L39-40  static int arm; static long n_plan_alloc, n_plan_calls, ...     (process-wide counters, initialised 0)
  L559    if(0 == strcmp(mode(), "plan") && n_plan_calls == nth()){       selects the NTH-th plan call
  L560    arm = 1;                                                        arm is set only inside that call
  L561    __real_fft_plan_dft_2d(...)                                     the plan is created with arm == 1
  L562    arm = 0;
  L60     if(1 == arm && 0 == strcmp(mode(), "plan")){                    the malloc wrapper counts only while arm == 1
  L61     n_plan_alloc++;
  L62     if(n_plan_alloc == nth()){  ... return NULL;                    fails the NTH-th malloc while arm == 1
  Grep result: n_plan_alloc is initialised at L40 and is never assigned again (only ++ at L61).  So it is a process-wide
  counter that is incremented only while arm == 1.  arm == 1 holds only during the single plan call selected at L559
  (n_plan_calls == nth()).  Consequence: n_plan_alloc counts the wrapped mallocs of the selected plan call, starting from 1
  at its first wrapped malloc, because no other plan call increments it.  The test at L62 therefore asks: "does the selected
  plan call make at least NTH wrapped mallocs?"  If yes, the NTH-th one fails.  If no, nothing is injected (hit 0).
  My reading: the one value NTH is used for two different things, "which plan call" (L559) and "which malloc inside that
  call" (L62).  A plan call with fewer than NTH wrapped mallocs can never be hit at NTH.  This matches the measured reachability
  (NTH 1 and 2 reached, NTH 3 and above not), but the number of wrapped mallocs per plan call was NOT counted in R3, so this
  is an inference (ERRATA_3 f4).  R4 measures it (section R4-4, gdb breakpoint counts or the call sequence).
  Open point (not claimed): the R3 data show NTH 1 and 2 reached for fft and kottke at once and twice; whether NTH 2 is reached
  by a second wrapped malloc of the first plan call or of another call is NOT established by the source reading alone.
