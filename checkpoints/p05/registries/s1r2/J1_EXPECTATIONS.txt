二、写入时点（矩阵何时被修改）
  FMMGetEpsilon_FFT（三树同序）：
    1) 先写 Epsilon2 的上半部分（由 Fto 取值），再 SetMatrix 与 LinearSolve 写 Epsilon_inv；
    2) 之后在 w=0..3 循环中，每次 fft_plan_exec 后写 Epsilon2 的一个 n×n 块。
    B 树：第 1 步的 LinearSolve 返回的 solve_info 被丢弃；fft_plan_exec 返回值被丢弃。
    H 树：LinearSolve 的 solve_info 检查（不为 0 则 ret=1，goto cleanup）；fft_plan_exec 检查。
  FMMGetEpsilon_PolBasisVL（三树同序）：
    1) S4_malloc(ivalues)（PB-ivalues，NTH=3 的候选），B 无 NULL 检查；A、H 有 NULL 检查并返回 1。
    2) S4_malloc(work)（PB-work，NTH=4 的候选），B 无 NULL 检查；A、H 有检查。
    3) S4_malloc(vfield)（PB-vfield，NTH=5 的候选），B 无 NULL 检查；A、H 有检查。
    4) 之后才调用 Simulation_AddFieldToCache（B 树无返回检查；H 树检查返回值）。
    5) 之后才对 Epsilon2 写入：RNP::TBLAS::Axpy 与 MultMM（每个 w 块）。
  因此，在 PolBasis 内部的 S4_malloc 失败（PB-ivalues、PB-work、PB-vfield）时，
  PolBasis 在写 Epsilon2 之前即返回，Epsilon2 应保持 FFT 原值（未被 PolBasis 修改）。

三、三树期望（以下为运行前的期望，单位：矩阵内容状态）
  树 B（37a82e8，无检查）：
    - PB-ivalues（NTH3）、PB-work（NTH4）、PB-vfield（NTH5）注入时，PolBasis 在写 Epsilon2 前返回或崩溃。
      期望：Epsilon2 = FFT 原值（块 1–4 全部为 FFT 写入值），Epsilon_inv = FFT 结果。
      但 B 树没有检查返回值：B 上 PolBasis 的失败若为 CRASH（无 NULL 检查后解引用，如 vfield 写入），
      则矩阵状态未定义（崩溃前未必一致）。此为 REG_3C2 中 fftnv 的 CRASH 情形。
    - 失败被丢弃：ComputeLayerModes 继续到 SolveLayerEigensystem，使用混合或原值矩阵，返回 0。
      期望最终类别：SILENT_SWALLOW（fftjones、fftvl）与 CRASH（fftnv）。与 REG_3C2 一致。
    - 结论期望：B 上存在"矩阵被后续求解使用、且失败被丢弃"的路径；但"混合状态（部分块已更新）"
      在 PolBasis 前即返回的注入点上不应出现，因为 PolBasis 在写入前失败。
      若出现混合（例如 vfield 注入后 Epsilon2 的某块已更新），则是 B 上的意外，需记录为新观察。
  树 A（876181c，fmm_ret 存在但 FFT 与 PolBasis 未串接）：
    - PolBasis 失败返回 1 -> fmm_ret=1 -> DiscardLayerModes -> return 20。期望最终类别：REPORTED_FAILURE。

      但本注入不针对 FFT，因此不在本条期望内。

  树 H（64eb0b5，全部检查）：
