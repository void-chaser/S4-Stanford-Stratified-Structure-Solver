# ERRATA_RELR4.txt -- P05 交付轮 REL-R4 执行与判定口径的补充记录（预注册之后新增，不改原预注册）

规则：PREREG_RELR4.tsv 在首次正式运行前写定（sha256 90bb8884b7346857e29e22e1d3cc53aeff748bdddd0774240337ad1b02d939df）；
之后期望值一律不改。本文件只记录判定*实现口径*的补充与执行事件，不改变任何预注册类别或容差。

## ER4-1 U 的 Lua 前端在脚本错误时退出码为 0
- 现象：U（7fd00a2）的 build/S4 在 Lua 脚本抛错（GetRealMaterial 为 nil、loadstring 为 nil、脚本语法错误）时仍以 rc=0 退出，
  stderr 有 Lua 错误与 traceback；B/F4 的同类错误 rc=1（P04 的前端重写修正了退出码）。
- 证据：EXPECT_SCAN_RELR4.tsv（失败原因分类）、VERDICT_RELR4.tsv 中 T1CMP_1d__Christ…fig2b /
  convergence__1d__binary_grating / cellA / cellB / ex2__fig2 / resonance_pos__ref / magneto__slab 的 detail
  （"silent-exit-0 with Lua error: U"）、REL-R1 的 38 SAME/11 BOTH_FAIL 复现。
- 处理：本轮对"有效通过"的定义为 rc==0 且 stderr 无 Lua 错误标记；U 的 rc 不能单独作为通过判据。
  该口径在预注册中没有写死（预注册只写类别与容差），因此不构成改期望；如按裸 rc 判定，这 7 个单元会被误计为
  REGRESSION（U pass / F4 fail），实际是两树同样失败的既有问题。
- 影响单元：T1 的 7 个既有失败示例；类别由误判的 REGRESSION 修正为 BOTH_FAIL。

## ER4-2 T3 MPI 频率匹配只在 IEEE double 完全相同的频点上判值
- 规则：预注册 criterion 为"相同频率上的值相对差 <= 1e-12；浮点循环可能让各段边界的频点重复或缺失，频点覆盖情况只记录，不算失败"。
- 事实：Lua 数值 for 循环在单进程（0.25..0.7, step 0.005）与 4 个 rank（起点为 0.25 + r/4*0.45，
  再 step 0.005）中累积方式不同，90 个频点里只有 23 个（rank0 的前 23 个）与单进程频点是完全相同的 double；
  其余 67 个只差最后几位。把"打印后相同的十进制文本"当作相同频率会错配 1-ulp 不同的频点，
  在共振陡峭处产生 1.458e-12 的差值（观测值，记录在 MPI_RELR4.tsv 的 detail）。
- 处理：判值只在 IEEE double 完全相同的频点上进行（23 点，最大相对差 0），覆盖率与"按打印文本匹配"的观测值
  都只记录、不判失败。这是对"相同频率"的实现口径澄清，不改预注册的 1e-12 容差。

## ER4-3 T2 两树比较用 rc 判运行是否成功
- 规则：T2 的类别是"与提交的参考数据是否一致"，不是"两树是否都通过"。
- 处理：U vs F4 / B vs F4 的 T2 比较中，"运行成功"按 rc==0 判定（U、B、F4 的 simple/fresnel/fanfig12 运行 rc 均为 0），
  数值差异按参考容差归类；否则 U 的 FAIL_REF 会被误标为 IMPROVED。

## ER4-6 end 门禁预跑首跑 1 项 FAIL（自指检查），正式 end 之前修正
- 事件：第一次预跑（--out GATE_RELR4_pre.txt，提交 (i) 之后）出现 1 项 FAIL：GATE_PRE_FILE_PRESENT。
  原因是预跑时该检查要求"GATE_RELR4_pre.txt 已存在"，而该文件正是本次运行自己的输出（自指）。
- 处理：把该检查改为只在正式 end 相（formal）运行（预跑不可能看到自己的输出；正式运行时预跑文件已存在）；
  首跑预跑文件保留为 GATE_RELR4_pre_firstrun.txt（sha256 3a5cbcb7174f406a50f455f752e57519c0d97a0ad9e0cd267eba50034f826b64，
  门禁输出文件不纳入证据清单）。这次修正发生在提交 (i) 之后，故对提交 (i) 做了 amend（仍是"两个本地提交"中的 (i)，
  没有第三条提交；提交信息不变、仍以 awaiting user review 结尾）。修正后预跑 85/85 FAILS=0，随后正式 end 只运行一次：
  86/86 FAILS=0 FINAL_STATUS=COMPLETE（附录 C）。

## ER4-7 判定引擎在正式 end 之前的两处实现修正
- (a) 有效通过口径（ER4-1）在初版判定引擎里只用于分类、没有写进 VERDICT 的 U/B/F4 状态列，
  导致 BOTH_FAIL 行的 U 列显示 PASS；修正为状态列也用"rc + stderr 错误标记"的有效结果。
- (b) T3 的"相同频率"初版按浮点容差匹配，会把只差 1 ulp 的频点当作相同（产生 1.458e-12 的错配观测）；
  修正为只在 IEEE double 完全相同的频点上判值（ER4-2），覆盖率与错配观测只记录。
- 两处修正都发生在第一次正式 end 门禁之前，只影响判定表（VERDICT/SUMMARY/RESULTS/MPI_RELR4）的生成，
  不改变任何预注册期望或容差；修正后重新生成了 registry 与证据 SHA256SUMS，再提交 (i)（amend 见 ER4-6）。
