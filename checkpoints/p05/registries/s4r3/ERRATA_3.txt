== a. R2 "45 rows" is 15 cases x 3 trees, not 45 points ==
RESULTS_R2.tsv has 45 data rows (header excluded): 15 rows for BASE, 15 for CUR, 15 for F.  Each of the 15 cases
is run on the three trees.  The 15 cases are: C0 (control, 3 trees), AL01, AL02, AL03, AL04, AL05, AL06, AL07, AL08,
AL09, AL10, AL11, P01, EX01, EX02 (not counting the tree suffix).  That is 3 control rows and 42 injection rows
(14 per tree: 14 injection cases x 3 trees), not 45 points.

Exact F-column count (commands run in R3-0, read-only):
  awk -F'\t' 'NR>1 && $2=="F"' RESULTS_R2.tsv | wc -l                  -> 15 F rows
  awk -F'\t' 'NR>1 && $2=="F" && $12>=1' RESULTS_R2.tsv | wc -l          -> 11 F rows with hit >= 1
  awk -F'\t' 'NR>1 && $2=="F" && $12==0' RESULTS_R2.tsv | wc -l          -> 4 F rows with hit = 0
  awk -F'\t' 'NR>1 && $2=="F" && $12>=1{print $1}' RESULTS_R2.tsv | sed 's/-F$//' | sort -u | wc -l  -> 11 distinct points
The 4 F rows with hit = 0 are: C0-F (control, expected 0) and AL05-F, AL08-F, AL11-F (NTH5, not reached).
The 11 reached F points are: AL01 AL02 AL03 AL04 AL06 AL07 AL09 AL10 EX01 EX02 P01.
So the effective F hit count is 11 points, which is what the R2 report's "about 11" means.  The R2 report's "45 rows"
wording is corrected by this entry: it is 45 run rows (15 cases x 3 trees), not 45 points.

== b. R2 AL01-AL11 and R1 AL01-AL18 are different identifiers ==
R2 registry v2 (REGISTRY_S4_PRE_R2_v2.tsv) uses AL01-AL11 for injection rows in the "fft" and PolBasis modes.  R1
(REGISTRY_S4_PRE.tsv) uses AL01-AL18 for source sites.  The same identifier means different things:
  R1 AL01 = S4/fmm/fmm_closed.cpp:40 ivalues (ClosedForm).   R2 AL01 = the fft-mode work allocation (NTH 1, 6144 B).
  R1 AL02 = S4/fmm/fmm_experimental.cpp:40 ivalues.          R2 AL02 = the fft-mode discval allocation (NTH 2, 16 B).
  R1 AL03 = S4/fmm/fmm_FFT.cpp:74 work.                      R2 AL03 = Jones NTH 3 (observed 10720 B, see c and d).
RULE FOR R3: the identifiers AL01-AL18 are NOT reused as new point ids in R3.  New point ids use
"M-<route>-<mode>-<category>-<NTH>" (route = once or twice, mode, category = malloc/plan/exec, NTH = gdb global call
index).  The R1 identifier is kept only in the column r1_id, written by source site.  Correspondence of the R2 names to
the R3 point ids is given in section e.

== c. R2 T-2, T-3 and T-8 are rule violations, not "legitimate targets" ==
The R2 report (P05_S4R2_REPORT.md section 8.2) describes T-2, T-3 and T-8 as "the target is legitimate".  That is not
a complete account.  They ran shell commands that write files (redirections or tar -x) without going through
testing/d003/safe_run.sh, which is the violation of the write-path rule (P05 hard rule, MEMORY.md).
  T-2  R2-0  git ls-tree ... > "$EV/tmp/F_expected_blobs.txt"          bare redirection, no safe_run     written: YES
  T-3  R2-2  git archive 1c11905 S4 | tar -x -C "$EV/tmp/seamchk"  2>/dev/null   bare, AND stderr hidden  written: YES
  T-8  R2-2  find S4 ... | while read ... printf ... > "$EV/tmp/F_export_blob.txt" ; git ls-tree ... > "$EV/tmp/F_git_blob.txt"
        bare redirections, no safe_run                                   written: YES
The target paths were inside the repository ($EV/tmp).  That is why they are not "out-of-repo writes"; it does NOT make
the commands compliant.  In the R3 record they are listed in table two (tool and script events), with the rule that
was broken, and not in table one.  T-3 additionally hid stderr (2>/dev/null), which the rule also forbids.

== f. plan injection reachability: measured facts, and a correction of an earlier reading (R3-4, after the YES sweep) ==
f1. Measured (tree F, route once, all modes, YES and out-of-scope rows together): a plan injection with NTH 1 and NTH 2
    is reached (hit = 1) in every mode tested (fft, kottke, closed1d, jones); NTH 3 to 12 are NOT reached (hit = 0).
    Tree B is the same (checked in the sweep).  The 22 INVALID YES points are exactly the fft and kottke plan NTH 3-5 and
    12-16 (route once and twice).  The 348 INVALID out-of-scope rows are the same pattern (plan NTH >= 3).
f2. The earlier reading in the sweep notes, "a plan injection can only hit NTH 1", is WRONG and is withdrawn: NTH 2 is
    reached.  Correct statement: plan NTH 1 and 2 are reached; NTH >= 3 is not reached with this injector.
f3. A reading I made and then corrected: the line "S4FMM HIT real malloc failure: plan preparation 24 B (hit=2)" in the
    closed1d log shows n_plan_alloc = 2 (the value printed in that line is n_plan_alloc, not the hit count).  The hit count
    is HITCOUNT 1 in the same log.  So "hit=2" in that line is not two hits.
f4. Mechanism (inferred, NOT measured): the injector counts the NTH-th plan call (n_plan_calls == nth) and, inside that
    call, fails the NTH-th malloc (n_plan_alloc == nth).  If fft_plan_dft_2d makes at most two wrapped mallocs per call,
    NTH >= 3 can never be reached.  The measured reachability is consistent with that, but the number of wrapped mallocs
    per plan call was NOT counted in R3.  This is an R4 measurement item.  Until it is measured, the INVALID plan points
    are INVALID by measurement, and their cause is an inference.
f5. Consequence for the coverage claim: plan NTH >= 3 (FMM and out-of-scope) is NOT covered by this injector.  It is not
    a red point and it is not repaired.  It is listed as UNCOVERED (INVALID by measurement) in the report.
