# P05-S1R Q2：VL NB=1（O-1）归属结论

> **状态：未完成，等待用户审核。** 本文件是对 O-1 归属的**建议**，不是裁决。最终归属由用户决定。
> 本文件不宣布 P05-S1、S2、S3、S4 任一阶段完成。本文件不修改任何旧报告；对旧报告的更正只写在本文件中。
> 证据类型：**[实测]** 本轮 gdb、公共 API 或驱动的原始输出；**[源码]** 只读阅读源码；**[推断]** 由上两者推出但未直接观察；**[未验证]** 尚无证据。

## 1. 一句话结论（建议）

**建议把 O-1 归为类别 B（独立缺陷）：VL 基在 n_G=1 时，平面图案层的流场归一化把"零场"静默地变为 NaN 并返回成功；随后特征值求解以 info=2 失败，错误被报告在特征值环节而非根因处。O-1 不属于"D003 的静默错误数值"模式，但它是一个独立的、应单独登记的缺陷。** 其中"独立缺陷"的机理已实测，但两个开放项（见第 6 节）尚未闭合，因此该结论标为建议。

## 2. 与旧裁决（S3"O-1 不并入 D003"）的关系

**修订（部分）。**

- **保留的部分**：O-1 是显式报告的（公共 API 抛出 `RuntimeError`，驱动返回 rc=20）。这一点在 B、A、H 三树上一致（第 5 节），因此 O-1 不是 D003 所定义的"静默错误数值"。S3 的这一判断仍然成立。
- **修订的部分**：S3 的理由是"显式报告，不是静默错误数值"。本轮实测表明，**报告是显式的，但根因环节是静默的**：`pattern_generate_flow_field` 在 `1./max_field` 处把零场变为 NaN，并 `return 0`，没有任何检查（`pattern.c:2145–2152`，[源码]；`max_field = 0` 与 NaN 的值为 [实测 gdb]）。因此 S3 的理由只覆盖了"错误如何呈现给用户"，没有覆盖"错误在哪里产生"。
- **修订的依据**：第 3 节的机理链；以及 `fmm_PolBasisVL.cpp:98–112` 的 `allzero` 分支把 NG=1 的图案层流场网格强制为 1×1（[源码]），Jones 与 NV 在相同 NG=1 下网格为 8×8（[实测]）。

## 3. 对 S2R 报告第 410 行的更正

`P05_S2R_HARNESS_SUPPLEMENT.md` 第 410 行原文：

> VL NB=1–4 的控制失败（RC 20）：是既有行为，需在 S4 验证中明确其是否属于 D003。

**更正如下（只写在本文件中，不改旧文件）：**

1. "是既有行为"是正确的：该失败在 Master 基线 B 上即存在，A 与 H 上也存在（[实测]，第 5 节）。
2. "需在 S4 验证中明确其是否属于 D003"**不再是必要的开放问题**：S3 已在 `P05_S1R` 之前作出"不并入 D003"的决定（`S3_OPEN_ITEMS_AND_SCOPE_FREEZE.md:171`）；本轮的修订（第 2 节）将其改为"独立缺陷，单独登记"。因此 S4 不需要再"确定其是否属于 D003"，而是需要按第 7 节处理。
3. 原句的"RC 20"是**驱动的返回码**，不是公共 API 的异常类型。公共 API 上对应的是 `RuntimeError`（文本见第 4 节）。两者都来自 `Simulation_ComputeLayerModes` 的 `return 20`（`S4.cpp:2362`，[源码]）。

## 4. 失败触发条件与用户可见表现

### 4.1 触发条件（以 n_G 表述）

| NumBasis（请求） | n_G（进入 `Simulation_ComputeLayerModes` 时的 `S->n_G`） | 结果（VL，ClosedForm + PolBasisVL，默认选项） |
|---|---|---|
| 1, 2, 3, 4 | **1** | 失败：`info = 2`，rc 20 |
| 5, 6, 7, 8 | **5** | 成功 |
| 9 | **9** | 成功 |

- **阈值的因果变量是 n_G，不是 NumBasis**（[实测]：NB 1–4 全部 n_G=1，NB 5–8 全部 n_G=5）。NB=2、3、4 的 n_G 在 S3 中未确定，现已实测为 1。
- 机理：`G_select` 在 `*NG == 1` 时直接返回 G=(0,0)（`gsel.c:172–176`，[源码]）；对 NB 2–4，圆形截断的壳层回退使 n_G=1（[实测]）。
- **失败的充要条件（本构建、默认选项、图案层）**：图案层的流场网格为 1×1，即所有 G 分量为零（n_G=1 对应的 G 集合为 {(0,0)}，`allzero` 分支成立）。
- **只有 VL 基受影响**：Jones 与 NV 没有 `allzero` 分支，其 NG=1 网格为 8×8（[源码] `fmm_PolBasisJones.cpp:142–149`、`fmm_PolBasisNV.cpp:99–106`；[实测] `max_field` 值）。

### 4.2 用户可见表现（三树一致，[实测]）

- 公共 API：`RuntimeError`，文本为 `GetPowerFlux: The layer eigensystem could not be solved; no solution was returned`（B、A、H 逐字相同）。
- 标准错误：`Layer eigensystem returned info = 2`。
- 驱动：`RC first 20`，`RC retry 20`，rc 1。
- **不产生**静默的有限错误数值：公共 API 的 27 个 OK 结果均为有限值，失败只以异常呈现（第 5 节）。

## 5. 三树一致性（[实测]）

| 检查 | B | A | H | 结论 |
|---|---|---|---|---|
| 公共 API，VL NB 1–4 状态 | EXC | EXC | EXC | 一致 |
| 公共 API，异常文本 | 同 | 同 | 同 | 一致 |
| 公共 API，27 行状态 | — | — | — | 0 行不一致 |
| 驱动 NG 1–9，n_G 与 info | 同 | 同 | 同 | 一致（gdb，27 次运行，rc 0） |
| 特征值输入 NaN（NG=1） | 有 | 有 | 有 | 一致 |

H 与 B 在本失败上**没有差异**，因此不触发"H 与 B 不同且无法解释"的停止条件。Jones 行的通量在树间有 1e-14 量级的差异，与同一棵树内的重复运行差异同量级（[实测]，见 PROGRESS 记录），不归因于源码变化。

## 6. 机理链（[实测] 与 [源码]）

1. 图案层进入 `Simulation_ComputeLayerModes`，n_G=1（[实测] probe A）。
2. `FMMGetEpsilon_PolBasisVL` 调用 `pattern_generate_flow_field`（`fmm_PolBasisVL.cpp:140`）。
3. `allzero` 分支把网格设为 1×1（`fmm_PolBasisVL.cpp:105–106`，[源码]；[实测] `ngrid={1,1}`）。
4. 该 1×1 网格上的约束：边界穿越 4 条边，贡献 `+1, +1, −1, −1`（[实测] 条件断点 `pattern.c:1432 if c>0`），相互抵消，右端项 `b={0,0}`（[实测]）。
5. `sparse_linsolve_d` 得 `x={0,0}`（[实测]），场 `max_field = 0`（[实测] `pattern.c:2145`）。
6. `1./max_field = inf`，场乘以 inf 得 NaN（[实测] `vfield[0..1] = -nan`），`pattern_generate_flow_field` **返回 0**（无检查，`pattern.c:2146–2152`，[源码]）。
7. NaN 进入 `Epsilon_inv` 与 `Epsilon2`（[实测] `pB->Epsilon_inv[1]` 在 `FMMGetEpsilon_PolBasisVL` 返回后即为 NaN）。
8. 特征值求解返回 `info = 2`（[实测] `SolveLayerEigensystem` 的 finish 值为 2；`rcwa.cpp:883` 打印），`ComputeLayerModes` 返回 20（`S4.cpp:2356–2362`，[源码]）。

**几何核对（[推断]，由独立 Python 计算）**：半径 0.25、圆心在原点的圆穿过该 1×1 单元的四条边，相对符号与测得的 `+1,+1,−1,−1` 一致（全局符号约定不影响抵消）。因此"抵消"是该闭合单元上的真实净穿越通量，而不是逐边符号错误。

**对照（[实测]）**：
- 同一 NG=1、同一几何：Jones、NV 的 `max_field = 0.0402`（非零），特征值求解成功（`info = 0`）。
- 只有均匀层的堆栈（无图案层）：三种基在 NB 1 与 9 均成功，B、A、H 三树各 6 个 OK、0 个 EXC（[实测] `public/uniform*`）。
- 反事实（仅改 `allzero` 分支，`cf/` 草稿树，`S4/` 未改）：VL NB 1–4 由失败变为成功，通量 0.95890；NB 5–9 与原值相差约 1e-13（未走该分支）。

## 7. 对 S3 收尾与 P05-S4 的指令（建议，由用户决定）

1. **不要把 O-1 当作 D003 的"静默错误数值"来修复**：其显式报告模式不符合 D003 的危险模式定义。但也**不要把它排除为"既有行为、无需处理"**，因为根因环节是静默的（第 2、6 节）。
2. **S4 是否把 VL NB=1–4 当作控制失败排除**：建议**不**作为 D003 的控制失败排除，因为该失败的根因是图案层的静默 NaN（独立缺陷），而不是 D003 驱动控制路径的正常行为。若 S4 的控制组需要排除它，应显式列为"已知独立缺陷的排除项"，并附本文件作为依据。
3. **是否记为已知限制**：建议记为**已知限制**，直到用户决定其登记方式。
4. **是否单独登记为新缺陷**：建议**单独登记**（草稿见 `P05_S1R_O1_ISSUE_DRAFT.md`）。登记表本身属于 P05-S5，本轮不修改。
5. **修复的范围**（仅建议）：`allzero` 分支与流场归一化的零场检查，二者都在 `S4/` 中，属于 S4 阶段（需用户授权），不属于 D003 装置的 testing/ 范围。

## 8. 本结论最强的证据与最弱的环节

**最强**：
- 机理从源码到运行时值形成完整闭环，每一步都有 gdb 实测（第 6 节），且三树一致。
- 单一改动的反事实（diff 已核对，仅一处）消除了 NG=1 失败，且不改变其他 NB 的结果（约 1e-13）。
- 失败在公共 API 与驱动两条路径上一致。

**最弱（两个开放项，未闭合）**：
1. **反事实通量的正确性未经独立参考验证。** NB=1 的三种基通量分别为 Jones 0.97136、Normal 0.97441、VL 反事实 0.95890。三者是不同的公式化，不要求精确一致，因此 1–2% 的差异**既不证明反事实正确，也不证明它错误**。这是"B"的主要缺口。
2. **`allzero` 分支的设计意图未知。** 源码无注释，历史仅见于宽泛的 `c0a8e69` 提交。FFT 路径（`fmm_FFT.cpp:55–60`）有相同的 `allzero → 1×1` 约定，但 FFT 不调用流场归一化器（经 `Pattern_DiscretizeCell` 构造，[源码]）。因此该约定是共享的，而"零场→NaN"的步骤仅在流场路径上。若用户确认 1×1 网格是有意的设计，则问题在于归一化对零场的处理（仍是缺陷），而不是网格本身。

**因此，若用户要求"反事实通量正确"作为 B 的前提，则该问题应标为类别 C（无法判定）**，所需证据是 NG=1 的独立解（例如更高 NB 收敛序列的外推，或与解析参考的比较）。
